## 1. 하네스 엔지니어링이란 (핵심 개념 요약)

여러 자료가 공통적으로 말하는 정의는 다음과 같습니다.

- **하네스(harness)** 는 모델의 가중치를 건드리지 않고, **모델 "주변"의 권한·도구·검증·관측을 설계**해 에이전트가 자율적으로 일하게 만드는 작업 환경입니다. ("around the model")
- 성능을 가르는 것은 모델 자체가 아니라 **그 모델을 감싼 구조**입니다. 하네스가 잘 설계되면 더 저렴한 모델로도 좋은 결과를 낼 수 있고, 부실하면 좋은 모델도 결과가 나쁩니다.
- 초점이 **"프롬프트 작성"에서 "시스템 설계"로** 이동합니다. 작업 분리, 지식 고정, 검증 루프, 협업 패턴이 결과를 크게 좌우합니다.
- 실무적으로는 **멀티 에이전트 오케스트레이션** 구조로 수렴합니다: 에이전트 팀을 만들고(TeamCreate), 작업을 배분하고(TaskCreate), 팀원끼리 직접 통신(SendMessage)하게 합니다.
- 구성의 3요소는 **에이전트 · 스킬 · 오케스트레이터**이며, 파일로 존재합니다: `.claude/agents/`, `.claude/skills/`, 그리고 `CLAUDE.md` 포인터.

> 이 개념은 본 저장소의 예제 및 [`doc/목차.md`](./목차.md)·[`doc/예제코드.md`](./예제코드.md)에서 다루는 내용과 동일한 흐름입니다.

## 6. 참고: 6가지 아키텍처 패턴 (자료 공통)

여러 한국어 자료와 `revfactory/harness`가 공통으로 정리하는 팀 아키텍처 패턴입니다. 본 저장소의 예제와도 대응됩니다(→ [`doc/목차.md`](./목차.md) 8장 참고).

1. **파이프라인** — 순차 처리, 앞 결과가 뒤 입력
2. **팬아웃 / 팬인** — 같은 입력을 병렬로 뿌리고 하나로 통합
3. **전문가 풀** — 라우터가 조건부로 전문가 호출
4. **생성-검증** — 만들고 검사하고 다시 만드는 품질 게이트
5. **감독자** — 런타임 중앙 동적 분배
6. **계층적 위임** — 총괄 → 팀장 → 실무자(재귀)
