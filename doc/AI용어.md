## RLHF (Reinforcement Learning from Human Feedback)

**인간 피드백 기반 강화학습.** 사람의 **선호(preference)** 를 학습 신호로 삼아 언어 모델을 **정렬(align)** 하는 훈련 기법. 모델이 정답을 맞히는 것을 넘어 **유용·안전·정직하게** 답하도록 다듬는 단계다.

### 왜 필요한가
"도움이 된다 / 해롭지 않다 / 정직하다"는 품질은 정답 라벨로 정의하기 어렵다. 대신 사람에게 **"둘 중 어느 답이 더 나은가"** 를 물어 그 선호를 모델에 주입한다.

### 3단계 파이프라인
```
사전학습 모델 → ① SFT → ② 보상 모델(RM) → ③ 강화학습(PPO) → 정렬된 모델
```
1. **SFT (지도 미세조정)** — 사람이 작성한 모범 응답(prompt→응답)으로 미세조정해 "대화로 유용하게 답하는" 출발점을 만든다.
2. **보상 모델(RM) 학습** — 같은 프롬프트의 여러 응답에 **사람이 순위/선호**를 매기고(A > B), 그 데이터로 "응답에 점수를 매기는 별도 모델"을 학습한다. RM은 인간 선호의 **대리(proxy)**.
3. **강화학습(PPO)** — 언어 모델(정책)이 응답 생성 → RM이 **보상** 부여 → 보상을 높이는 방향으로 업데이트. **KL 페널티**로 원래(SFT) 모델에서 너무 멀어지지 않게 제약해 **보상 해킹**을 억제한다.

### 효과
- 정렬(3H: **Helpful · Honest · Harmless**), 지시 따르기, 안전성 향상.
- 대표 사례: InstructGPT / ChatGPT가 "쓸 만한 어시스턴트"가 된 계기.

### 한계·주의
- **비용·규모** — 사람 라벨링이 비싸고 느림.
- **보상 해킹(reward hacking)** — RM의 허점을 파고들어 "점수는 높지만 나쁜" 답.
- **선호 편향** — 라벨러의 관점·문화가 반영됨.
- **sycophancy(아첨)** — 사람이 좋아할 답에 치우쳐 사실성을 희생.

### 관련·대안 기법
| 기법 | 요지 |
|---|---|
| **RLAIF** | 사람 대신 **AI가 선호를 매김**(비용↓) |
| **Constitutional AI** (Anthropic) | 명시적 **원칙(헌법)** 에 따라 AI가 스스로 응답을 비평·수정 (RLAIF의 한 형태) |
| **DPO** (Direct Preference Optimization) | 별도 보상 모델·PPO 없이 **선호 데이터로 정책을 직접 최적화**하는 단순한 대안 |

### 하네스 엔지니어링과의 관계 (층위 구분)
| | RLHF | 하네스 엔지니어링 |
|---|---|---|
| 무엇을 바꾸나 | **모델 자체(가중치)** 를 훈련 | 모델은 그대로 두고 **주변(에이전트·스킬·도구)** 을 설계 |
| 시점 | 모델 **학습 시** | 모델 **사용 시(런타임)** |
| 목표 | 정렬(유용·안전·정직) | 작업 환경 표준화·재현성 |

> 한 줄 정리: **RLHF = 사람의 "이게 더 낫다"는 선호를 보상 신호로 바꿔 모델을 정렬하는 훈련법**(SFT → 보상모델 → PPO+KL). 하네스는 그렇게 정렬된 모델 **위에** 얹는 작업 환경이다 — "모델이 아니라 하네스가 결과를 결정한다"는 명제는 좋은 모델이라도 하네스가 실사용 성능을 좌우한다는 뜻.

## 멀티 에이전트 프레임워크 — AutoGen · CrewAI (· LangGraph)

여러 AI 에이전트가 **협업하도록 코드로 짜는 오케스트레이션 프레임워크**들. Claude Code 하네스와 목표(멀티 에이전트 협업)는 겹치지만, **코드 프레임워크**라는 점이 다르다.

### AutoGen (Microsoft)
- 여러 **대화형 에이전트(conversable agents)** 가 **메시지를 주고받으며** 문제를 푸는 것이 기본 추상화.
- 대표 구성: `AssistantAgent`(LLM), `UserProxyAgent`(코드 실행/사람 대리), `GroupChat` + `GroupChatManager`(발화 순서 조율).
- 강점: **코드 실행 루프**(작성→실행→관찰→수정)와 유연한 대화·인간 개입(human-in-the-loop).
- 근황: 이벤트 기반 재설계(0.4+) 후 Semantic Kernel과 수렴하는 **Microsoft Agent Framework** 방향으로 재편 중(명칭·API 변화 잦음 — 공식 문서 확인).

### CrewAI
- **역할(role)·목표(goal)·배경(backstory)** 를 가진 **Agent** + **Task** 를 **Crew(팀)** 로 묶어 실행. "역할 기반 팀" 은유.
- 실행 방식: **Crews**(순차·계층 프로세스 협업) / **Flows**(결정론적 이벤트 기반 워크플로).
- 강점: 직관적 추상화(역할·태스크·크루)로 빠른 팀 구성.

### 비교

| 항목 | AutoGen (Microsoft) | CrewAI |
|---|---|---|
| 핵심 은유 | 에이전트 간 **대화** | **역할 기반 팀(crew)** |
| 조율 | GroupChat/Manager, 이벤트 기반(0.4+) | Process(순차·계층) + Flows |
| 강점 | 코드 실행 루프, 유연한 대화·인간 개입 | 직관적 역할·태스크 모델, 빠른 구성 |
| 언어 | 주로 Python | 주로 Python |

> 함께 거론되는 **LangGraph**(LangChain 계열): 그래프/상태 기반 오케스트레이션으로 분기·순환·체크포인트가 강점.

### 하네스 엔지니어링과의 관계 (같은 문제, 다른 형태)
| | AutoGen · CrewAI · LangGraph | Claude Code 하네스 (본 책/저장소) |
|---|---|---|
| 형태 | 개발자가 **Python 코드**로 에이전트·흐름 조립 | 파일(`.claude/agents`·`skills`·`CLAUDE.md`)로 **선언** |
| 트리거 | 코드 실행 | **자연어** 요청(스킬 `description`) |
| 관점 | 코드 프레임워크 | "Agent = Model + **Harness**"(→ [`하네스자료.md`](./하네스자료.md) 7절) |

> 한 줄 정리: **"여러 에이전트를 협업시킨다"는 문제는 같고**, AutoGen·CrewAI·LangGraph는 이를 **코드 프레임워크**로, Claude Code 하네스는 **파일 규약**으로 푼다.
> 주의: 이 프레임워크들은 버전·명칭 변화가 빠르다 — 도입 시 각 공식 문서에서 최신 API를 확인할 것.
