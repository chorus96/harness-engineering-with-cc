# IEEE 1500 HBM PMBIST 컨트롤러 하네스

AXI4-Lite로 제어되는 IEEE 1500 컨트롤러(HBM PMBIST 구동) IP의 RTL 개발 하네스.

## 오케스트레이션 포인터
- 전문 에이전트는 `.claude/agents/`, 재사용 워크플로는 `.claude/skills/` 에 정의한다.
- 요구는 `docs/requirements.md` 의 추적 ID(REQ-*)로 관리한다. 설계·검증·리뷰는 이 ID를 참조한다.
- RTL 소스는 `rtl/`, 테스트벤치는 `tb/`, 제약은 `constraints/`, 실행 로그는 `run/` 에 둔다(관례 폴더).

## 작업 흐름 (파이프라인)
요구 정의 → 조사 → 설계 → 구현 → 검증 → 리뷰 → 배포 → 모니터링.
1. `spec-researcher` 가 요구·디바이스 제약을 정제한다.
2. `microarch-designer` 가 CSR 맵·FSM·CDC 계획을 ADR과 함께 설계한다.
3. `rtl-coder` 가 구현하고, `rtl-generate-verify` 스킬이 린트·시뮬 통과까지 반복한다(재시도 상한 3, 초과 시 사람 에스컬레이션).
4. `rtl-review-team` 스킬이 린트·CDC·타이밍·검증을 병렬 리뷰해 통합한다.
5. `run-synth` 결과와 사인오프는 사람이 최종 승인한다.

## 규칙 (Why-First)
- 모든 비동기 도메인 교차(`aclk` ↔ `WRCK`)는 명시적 동기화기를 둔다 — 왜냐하면 IEEE 1500 시프트 클록과 AXI 클록은 독립이라 메타스테이빌리티가 발생하기 때문.
- CSR는 AXI4-Lite 프로토콜 규약(단일 비트 위상, 미지원 주소는 SLVERR 또는 정의된 정책)을 반드시 준수한다 — 왜냐하면 상호운용성과 검증 재현성이 여기에 달렸기 때문.
- IEEE 1500 시퀀스는 `SelectWIR`/`ShiftWR`/`CaptureWR`/`UpdateWR` 순서를 어기지 않는다 — 왜냐하면 순서 위반은 래퍼 명령 손상으로 이어지기 때문.
- 검증자(리뷰) 에이전트는 코드를 수정하지 않는다 — 판정만 하고 수정은 `rtl-coder` 가 반영한다.
- 테스트·린트를 우회·비활성화해 통과시키지 않는다. 자동 커밋·자동 릴리스 금지.

## 안전장치
- 생성-검증 루프는 `MAX_RETRIES=3` 후 사람에게 에스컬레이션.
- 동시 활성 에이전트는 3~5명으로 제한한다.
- 최종 기능/타이밍 사인오프와 하드웨어 배포 승인은 사람이 담당한다.
