# 요구 정의 — IEEE 1500 HBM PMBIST 컨트롤러 (예시)

> 각 요구는 **추적 ID + 수용 기준(acceptance)** 을 가진다. 설계(ADR)·검증(테스트)·리뷰는 이 ID를 참조한다.
> 아래는 파일럿 스캐폴드용 **예시 요구**이며, 실제 값(주소 맵·타이밍 수치)은 사내 사양으로 대체한다.

## 1. AXI4-Lite 인터페이스

| ID | 요구 | 수용 기준 |
|---|---|---|
| REQ-AXI-001 | AXI4-Lite 슬레이브 CSR를 제공한다(AW/W/B/AR/R 5채널). | 프로토콜 체커(assertion)가 위반 0으로 통과 |
| REQ-AXI-002 | 데이터 폭 32비트, 바이트 스트로브(WSTRB) 지원. | 부분 쓰기 시 지정 바이트만 갱신 |
| REQ-AXI-003 | 미정의 주소 접근은 정의된 에러 정책(예: SLVERR)로 응답. | 미정의 주소 read/write에 정책대로 응답 |
| REQ-AXI-004 | 백투백 트랜잭션에서 데드락이 없다. | 랜덤 리그레션에서 타임아웃 0 |

## 2. IEEE 1500 컨트롤러

| ID | 요구 | 수용 기준 |
|---|---|---|
| REQ-1500-001 | WSC 신호(`WRCK/WRSTN/SelectWIR/ShiftWR/CaptureWR/UpdateWR`)와 `WSI/WSO`를 생성/수집한다. | 파형에서 신호 시퀀스가 표준 순서 준수 |
| REQ-1500-002 | WIR 로드→Capture→Shift→Update 시퀀스를 CSR 명령으로 개시한다. | 명령 레지스터 write 후 시퀀스 완료 플래그 set |
| REQ-1500-003 | 직렬 시프트 길이는 프로그래머블(체인 길이 레지스터). | 서로 다른 길이에서 WSO 데이터 정합 |
| REQ-1500-004 | 시퀀스 중 오류(타임아웃)는 상태 레지스터로 보고한다. | 강제 오류 주입 시 에러 비트 set |

## 3. HBM PMBIST 제어

| ID | 요구 | 수용 기준 |
|---|---|---|
| REQ-PMBIST-001 | PMBIST 알고리즘/주소범위/데이터 패턴을 CSR로 설정한다. | 설정값이 엔진에 반영(리드백 일치) |
| REQ-PMBIST-002 | 다수 HBM 채널/의사채널을 순차 또는 지정 순서로 구동한다. | 채널 순회 완료, 채널별 결과 수집 |
| REQ-PMBIST-003 | 결과(pass/fail, 최초 실패 주소)를 CSR로 노출한다. | 주입된 결함이 실패 주소로 보고됨 |
| REQ-PMBIST-004 | 실행 중단(abort)과 재시작을 지원한다. | abort 후 상태 클린, 재시작 정상 |

## 4. 클록·리셋·CDC

| ID | 요구 | 수용 기준 |
|---|---|---|
| REQ-CDC-001 | `aclk`(AXI)와 `WRCK`(테스트) 도메인 교차는 동기화기/핸드셰이크로 처리한다. | CDC 정적 분석 위반 0 |
| REQ-CDC-002 | 비동기 리셋은 도메인별로 안전하게 해제(리셋 동기화)된다. | 리셋 어서션/디어서션 리그레션 통과 |

## 5. 비기능

| ID | 요구 | 수용 기준 |
|---|---|---|
| REQ-NFR-001 | 합성성(synthesizable) 코딩 스타일을 준수한다. | 린트/합성 경고 정책 기준 이하 |
| REQ-NFR-002 | 타이밍 제약(XDC)이 목표 주파수에서 만족된다. | STA WNS ≥ 0(목표 클록) |
| REQ-NFR-003 | 기능 커버리지 목표를 만족한다. | 커버리지 ≥ 팀 목표(파일럿에서 확정) |
